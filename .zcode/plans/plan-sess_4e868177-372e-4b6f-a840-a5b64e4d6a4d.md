# 注册 + 管理员审批放权 功能实现方案

在 worktree 分支 `refactor/postgres-migration` 上叠加。基于已确认的三项决策:**仅拦截登录**、**内嵌设置页**、**登录页加切换**。

## 数据模型改动

### `schema.ts`:给 `appAccounts` 加 3 列
- `role text NOT NULL DEFAULT 'member'`,CHECK `IN ('admin','member')`
- `status text NOT NULL DEFAULT 'pending'`,CHECK `IN ('pending','approved','disabled')` —— 用 disabled 兼顾"拒绝"和"事后停用"
- `householdId` 已有(nullable)—— 注册时直接分配新 household

### 生成 Drizzle 迁移
`drizzle-kit generate` → `0001_*.sql`(ALTER TABLE ADD COLUMN),再 `migrate` 应用。

## 后端改动

### `auth.ts`
1. **`AuthAccount` 类型**加 `role: "admin"|"member"`、`status: AccountStatus`
2. **`seedDefaultAccount()`**:插 admin 时显式 `role:'admin', status:'approved'`(避免加列后默认 admin 变 pending 锁死全员——这是最大风险点)
3. **新增 `register(username, password)`**:校验用户名格式/唯一、密码强度(复用 `validPassword`)、为新用户生成新 `householdId`、插 `status:'pending'`;不创建 session
4. **`login()` 增加状态拦截**:`pending` 抛"账号待管理员审批"、`disabled` 抛"账号已被停用"、仅 `approved` 放行;返回带 role/status
5. **`session()` join 时一并取 role/status**(注意现有 `row?.householdId ? {...}: null` —— 注册时已分配 householdId,不会卡)
6. **新增管理员方法**:`listAccounts()`(全列表)、`setAccountStatus(username, status)`(审批/停用)

### 新增 API 路由
- `POST /api/auth/register/route.ts`:`{username, password}` → `register()`;无需登录。错误用 409(用户名已存在)
- `GET /api/admin/accounts/route.ts`:仅 admin(`requireAdmin` 守卫),返回账号列表(含 status)
- `PATCH /api/admin/accounts/[username]/route.ts`:仅 admin,`{status: "approved"|"disabled"}`

### `household.ts` 新增守卫
- `requireAdmin()`:调 `currentAccount()`,非 admin 或未登录抛错(403)。管理员路由统一用它

### `http.ts` 扩展错误码(最小改动)
新增 `errorResponse(error, fallback, status=400)` 可传状态码,默认仍 400。`requireAdmin` 用 403,register 冲突用 409。前端解析 `data.error` 不变。

## 前端改动

### `account-gate.tsx`(登录页)
- 加登录/注册表单切换(`mode` state)
- 注册表单:用户名+密码+确认密码 → POST `/api/auth/register`
- 成功提示"注册成功,请等待管理员审批",切回登录
- 保留底部默认账号提示(admin 自己能登录审批)

### 新增 `admin-accounts.tsx` 组件
- 列出所有账号(username/role/status/创建时间)
- pending 账号显示「通过」「拒绝」按钮;approved 显示「停用」
- 调 `/api/admin/accounts` 和 PATCH

### `inventory-dashboard.tsx` + `page.tsx`
- `page.tsx` 把 `account.role` 传给 dashboard
- dashboard「更多」标签页:当 `role==='admin'` 时插入 `<AdminAccounts />` 入口(类似已有的 `<AccountSettings>`)
- `AccountSettings`(改密码组件)顺带显示当前角色

## 验证
- 跑 `drizzle-kit migrate` 建表后,`seedDefaultAccount` 应让 admin 保持 approved
- vitest 已有 auth 无覆盖,本功能手动 dev 验证:注册→pending 登录被拒→admin 审批→用户登录成功
- 确认现有 admin/admin123 仍能登录(回归)

## 不在范围
- 不给现有业务路由补登录守卫(按你"仅拦截登录"的决策,匿名 household 仍可临时存数据;真正的登录强制留后续)
- 不做"邀请家人加入同一家庭"——沿用 1 账号 1 household
- 不做注册时的邮箱验证/验证码(家庭内网场景)

## 风险点(实现时重点处理)
1. **迁移后 admin 锁死**:加 status 列默认 pending,必须让 seed 显式 approved —— 优先验证
2. **session() 的 householdId 过滤**:新注册用户必须注册时就分配 householdId,否则 session 返回 null 登录不进
